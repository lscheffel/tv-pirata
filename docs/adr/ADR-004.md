# ADR-004: Persistência Relacional SQLModel, Gestão de Biblioteca e Servidor Web FastAPI

## 1. Contexto & Diagnóstico

As decisões fundamentais (ADR-001), arquiteturais (ADR-002) e os clientes de provedores externos com fallback resiliente e EZTV (ADR-003) estão consolidados e certificados. No entanto, o TV Pirata ainda não possui persistência relacional física para o catálogo do usuário nem um ponto de entrada HTTP exposto para a interface web.
Permanecem em aberto os débitos técnicos `TD-2026-001`, `TD-2026-002`, `TD-2026-003` e `TD-2026-004`. Faz-se necessário materializar a camada de dados relacional com SQLModel no SQLite e expor a API REST do FastAPI conectando todos os serviços.

## 2. Decisões & Decision Ledger

- **DEC-013 (Modelos Relacionais SQLModel para Biblioteca Pessoal):** Implementar as entidades `ShowRecord`, `SeasonRecord` e `EpisodeRecord` em `src/backend/models/db.py`, indexadas por `tmdb_id` (com `tvmaze_id` e `imdb_id` como chaves secundárias).
- **DEC-014 (Rastreamento Granular de Assistidos):** Implementar a tabela `EpisodeWatchRecord` contendo `episode_id`, `is_watched` (booleano) e timestamp `watched_at`, com métodos de agregação de progresso por temporada e série.
- **DEC-015 (Gestão de Mídia Local com Dupla Flag):** Implementar a tabela `LocalMediaRecord` vinculando episódios aos arquivos do SMB, com flags `is_available` (booleano) e `last_seen_at` (datetime), garantindo que arquivos ausentes nunca apaguem histórico de assistidos.
- **DEC-016 (Categorização Híbrida: Tags M2M e Smart Collections):** Implementar `TagRecord` com tabela associativa `ShowTagLink` para marcação manual livre, e `CollectionRecord` contendo `filter_criteria` em JSON para consultas dinâmicas salvas.
- **DEC-017 (Engine SQLite & Gerenciamento de Sessão):** Criar `src/backend/core/database.py` fornecendo gerenciamento de conexão SQLite (`data/tv_pirata.db`), inicialização determinística de esquemas (`init_db`) e injeção de dependência assíncrona de sessão no FastAPI.
- **DEC-018 (Servidor Web FastAPI e Rotas REST Modulares):** Implementar `src/backend/main.py` com CORS configurado e roteadores em `src/backend/api/`:
  - `/api/discovery`: busca, trending e detalhes (usando `ResilientDiscoveryService`).
  - `/api/library`: adição, remoção e listagem de séries salvas.
  - `/api/watches`: alternância de status de assistido por episódio/temporada e cálculo de progresso.
  - `/api/collections` e `/api/tags`: gestão de taxonomias e coleções inteligentes.
  - `/api/torrents`: listagem de links magnet via EZTV.

## 3. Alternativas Consideradas & Trade-offs

- **Alternativa A (Apenas Armazenamento Chave-Valor em JSON):** Rejeitada por não garantir integridade referencial, travar em consultas de progresso e violar a robustez em rede.
- **Alternativa B (ORM Pesado com Migrations Alembic no MVP):** Rejeitada por introduzir overhead desnecessário para um banco local em arquivo único nesta fase.
- **Alternativa C (SQLModel com Criação Atômica e Sessões FastAPI):** Aceita. Unifica validação Pydantic com SQLAlchemy e entrega queries ultrarrápidas em SQLite.

## 4. Consequências

- **Positivas:** Persistência atômica e independente de internet; API REST completa pronta para consumo do frontend; histórico de assistidos 100% blindado.
- **Negativas / Mitigações:** Necessidade de sincronizar alterações entre o modelo canônico da API (`UnifiedShow`) e os modelos de tabela (`ShowRecord`).
