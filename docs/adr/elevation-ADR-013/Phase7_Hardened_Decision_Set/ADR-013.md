## 2. Contexto & Diagnóstico

Embora a `ADR-012` tenha entregue `sources.db` multi-provedor e a aba **Fontes de Dados** (`SourcesView.tsx`), a incorporação contínua de novos provedores (`1337x`, `TGx`, `Nyaa`, feeds `Torznab` ou fontes diretas não-torrent) ainda exige alterações manuais em múltiplas camadas de backend e frontend, não oferece busca sob demanda (*Lazy*) para indexadores sem dump completo e não trata de forma segura bloqueios reCAPTCHA/Cloudflare em fontes únicas.

## 3. Registro de Decisões Canônicas (`Decision Ledger`)

| ID | Decisão Arquitetural | Módulos Impactados |
| :--- | :--- | :--- |
| **`DEC-001`** | **Separação `Adapter` vs. `Instância` (`1:N`) com Autodiscovery Seguro:** Introduzir `BaseSourceAdapter` e `@register_source_adapter` com descoberta automática via `pkgutil` em `src/backend/providers/sources/*.py` (com isolamento `try/except` de import para não derrubar `main.py`). `ExternalSourceRecord` ganha colunas aditivas (`adapter_key`, `source_kind`, `config_json`, `priority`, `cooldown_until`) via `ALTER TABLE` idempotente em `init_eztv_db`, mantendo `EZTVShow`/`eztv_metadata` intactos. | `sources_db.py`, `database.py`, `src/backend/providers/sources/`, `sources_registry.py` |
| **`DEC-002`** | **Adapters HTTP Enxutos (`Torrent-Api-py` + `Torznab` + `UniqueWeb`) Sem DOM Scrapers no Core:** Manter `EZTV` e `YTS v2` nativos e entregar adapters baseados estritamente em `httpx`: `torrent_api_py` (consumindo sidecar HTTP estilo `Ryuk-me/Torrent-Api-py` com presets `1337x`, `tgx`, `nyaasi`, `piratebay`), `torznab` (Prowlarr/Jackett) e `unique_web` (para fontes web diretas), com *circuit breaker* em **2 níveis** (instância individual vs. host base do sidecar). | `src/backend/providers/sources/eztv_adapter.py`, `yify_adapter.py`, `torrent_api_py_adapter.py`, `torznab_adapter.py`, `unique_web_adapter.py`, `pyproject.toml` |
| **`DEC-003`** | **Motor `Lazy-Cache` (TTL 24h) + Proveniência `EntityResolutionService`:** `GET /api/sources/releases` retorna cache local `< 20ms`; quando ausente ou com `last_checked_at` > TTL (`24h` default), consulta em paralelo (`asyncio.gather` + timeout + `AbortController` no frontend) os adapters de busca ativos, mantendo cache expirado como *fallback offline*. Resultados sem `imdb_id` usam `EntityResolutionService`: confiança **`>= 0.85`** grava em `ExternalRelease` (`matched_by`, `match_confidence`, acendendo `MediaBadge`); **`0.60–0.84`** vai apenas em `approx_matches` voláteis para o `TorrentModal` com input de refino manual. | `sources_registry.py`, `entity_resolution.py`, `sources_db.py`, `api/sources.py`, `TorrentModal.tsx` |
| **`DEC-004`** | **Fallback Assimétrico (`torrent_mirrorable` vs. `unique_web_source`) & Segurança Zero-Trust:** Fontes `torrent_mirrorable` rotacionam `mirrors[]` automaticamente; fontes `unique_web_source` ao detectar reCAPTCHA/Cloudflare retornam `status: "challenge_required"` e `challenge_url` em `source_diagnostics`, exibindo cartão `44×44px` **"Abrir Página no Navegador"** + **"Tentar Novamente"** no `TorrentModal.tsx`. Todas as URLs passam por whitelist (`http`, `https`, `magnet`), segredos `secret=True` são mascarados (`••••`) na saída API e protegidos contra sobrescrita por sentinel (`RT13-02`). | `sources_registry.py`, `api/sources.py`, `TorrentModal.tsx`, `types.ts` |
| **`DEC-005`** | **Deshardcoding Total de Filtros/UI & Suíte Contratual Universal (`pytest` + `respx`):** Remover hardcodings `yify`/`1337x` em `canonical_taxonomy.py`, `discovery_engine.py` e `ExplorerView.tsx` lendo instâncias de `external_sources` dinamicamente (invalidação coordenada de `discovery_cache`); adicionar formulário dinâmico via `config_schema`, **"+ Adicionar Fonte"** e **"Testar Conexão"** (`POST /api/sources/{key}/test`) em `StatusConfigView.tsx`; criar suíte parametrizada validando contrato universal de todo adapter registrado. | `canonical_taxonomy.py`, `discovery_engine.py`, `api/sources.py`, `StatusConfigView.tsx`, `ExplorerView.tsx`, `tests/integration/test_source_plugins_contract.py` |
