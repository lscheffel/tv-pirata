# Fase 5: Registro de Amplificações Arquiteturais (Amplification Register)

| ID | Amplificação Promovida ao Blueprint | Problema Mitigado | Impacto |
| :--- | :--- | :--- | :--- |
| **AMP-001** | **Fallback Pós-Paginação para `episodes_count == 0`:** Se uma série na página atual tiver `episodes_count == 0`, consultar `_build_episode_stats_map` apenas para os IDs fatiados da página (máx. 20 IDs) usando o índice `idx_episodes_show_season_ep`. | Garante que fixtures de teste que inserem `EZTVEpisodeCatalog` diretamente sem chamar `init_eztv_db()` após o insert continuem exibindo `episode_count`, `max_season` e `max_episode` exatos. | Zero regressão em testes e performance $< 0,2\text{ ms}$. |
| **AMP-002** | **Table Version Fingerprint na Chave do Cache Escopado:** Combinar `(id(engine), id(eztv_engine))` com contadores ultrarrápidos `(count_shows, max_updated_at)` / `(count_works, count_eztv_shows, count_catalog_shows)`. | Invalida automaticamente o cache sempre que qualquer teste ou rota adicionar/modificar registros, mesmo sem chamada manual a `invalidate()`. | Coerência de cache 100% determinística. |
| **AMP-003** | **Sanitizador de Query `FTS5` com Fallback `ILIKE`:** Extrair tokens seguros (`re.findall(r"\w+", q)`) formatados como `"token"*` antes de consultar `shows_fts MATCH`, caindo para `ILIKE` caso a expressão contenha apenas símbolos ou não encontre matches exatos de prefixo. | Previne `sqlite3.OperationalError: fts5: syntax error` em títulos com pontuação (`9-1-1`, `Mr. & Mrs. Smith`, `Spider-Man:`). | Resiliência total em buscas de usuário. |
| **AMP-004** | **Overlay Dinâmico de Usuário no `DiscoveryEngineRepository`:** Cachear apenas o catálogo base e o lookup EZTV, mantendo `lib_by_imdb` (`ShowRecord`) e `watched_show_ids` (`EpisodeWatch`) avaliados em tempo real sobre o snapshot. | Garantir que favoritar uma série ou marcar episódio assistido reflita imediatamente em `/api/explore/works` sem precisar reconstruir o grafo de obras. | Consistência imediata + velocidade de cache. |
