# ADR-002: Provedores de Descoberta, Fallback Resiliente e Gestão de Mídia (Schema v1)

## 1. Contexto & Diagnóstico

A partir das conclusões do ciclo dialético de Garimpo (Schema v1), estabeleceu-se a necessidade de um ecossistema de backend que una descoberta online veloz, obtenção simplificada de torrents e rastreamento local de arquivos e histórico de reprodução.
A dependência exclusiva de uma única API (ex: TMDB) cria pontos únicos de falha por instabilidade de rede ou esgotamento de cotas. Além disso, a separação entre catálogo virtual e arquivos reais no SMB exige um modelo relacional que suporte arquivos que entram e saem do disco sem degradar a integridade dos dados de visualização.

## 2. Decisões & Decision Ledger

- **DEC-004 (Contrato Unificado com Fallback TVMaze):** Implementar `UnifiedShow` em Pydantic v2 com adaptador TMDB prioritário e fallback automático para TVMaze em caso de timeout de 2.0s ou HTTP 5xx/429.
- **DEC-005 (Integração Leve com EZTV API por IMDB ID):** Obter o `imdb_id` a partir do TMDB/TVMaze e consultar a API pública da EZTV (`get-torrents?imdb_id=...`) para fornecer magnets e contagem de seeds/peers sem embutir cliente torrent no servidor.
- **DEC-006 (Controle Granular com Dupla Flag de Disponibilidade):** Tabela `episode_watches` por episódio e flags `is_available` + `last_seen_at` para indicar se o arquivo físico está acessível no compartilhamento SMB sem apagar histórico se desconectado.
- **DEC-007 (Categorização Híbrida: Tags M2M + Smart Collections):** Suporte a tags relacionais manuais (`tags`) e coleções inteligentes baseadas em filtros JSON estruturados (`filter_criteria`).
- **DEC-008 (Pirâmide de Testes Desconectada com Fixtures e Respx):** Testes unitários e de integração 100% determinísticos e offline em `tests/`, utilizando fixtures JSON de TMDB/TVMaze/EZTV e interceptador `respx`.

## 3. Alternativas Consideradas & Trade-offs

- **Alternativa A (Exposição de JSONs Brutos das APIs):** Rejeitada por quebrar o contrato do frontend no chaveamento para o TVMaze.
- **Alternativa B (Cliente BitTorrent Embutido):** Rejeitada por introduzir dependências C++ nativas e desvio da função de descoberta.
- **Alternativa C (Contrato Unificado + Fallback + EZTV Leve):** Aceita. Máxima resiliência e zero acoplamento operacional.

## 4. Consequências

- **Positivas:** Catálogo sempre funcional mesmo sob falha do TMDB; visualização imediata de links magnet para download; histórico de assistidos totalmente protegido contra limpezas de disco.
- **Negativas / Mitigações:** Campos exclusivos do TMDB (como trailers secundários) ficam nulos no fallback do TVMaze (mitigado com tipagem `Optional[T] = None`).
