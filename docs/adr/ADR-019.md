# ADR-019: Integridade do Acervo YIFY/YTS: Prioridade de Mirrors API v2, Filtro por Formato na Ingestão e Auto-Cura de Presença Fantasma

## 1. Contexto e Diagnóstico

Durante a inspeção do filtro `yify` no **Explorar**, foram observados títulos que exibiam disponibilidade na grade (`yts:presence:<imdb_id>`), mas ao abrir o modal de fontes (`TorrentModal`) retornavam **0 releases disponíveis** — e não existiam no acervo web oficial do YIFY.

A análise física de `data/sources.db`, `data/mainstream.db`, `sources-apis.md` e `yify_adapter.py` revelou três causas raízes acopladas:

1. **Divergência de catálogo entre `movies-api.accel.li` (`yts.pw`) e os domínios YTS tradicionais (`yts.mx` / `yts.lt`):** Embora `sources-apis.md` documente `https://movies-api.accel.li/api/v2/` como endpoint oficial da API v2, suas respostas retornam URLs de `yts.pw` (~66 mil entradas) contendo títulos históricos, séries de TV com `imdb_code` trocado (ex.: `tt0413550` *CMT Top 20 Countdown*, `tvSeries`) e itens sem torrents ativos na consulta detalhada.
2. **Ingestão Stage 1B sem validação de formato e hash:** `YIFYSourceAdapter._movies_to_presence_candidates` persiste `yts:presence:<imdb_id>` sem verificar se o `imdb_id` pertence a uma obra de cinema (`movie`, `tvMovie`, `short`, `documentary`) em `data/mainstream.db` e sem validar se o `hash` do torrent é válido.
3. **Ausência de auto-cura no Stage 2 JIT quando a busca ao vivo volta vazia:** Em `SourcesRegistryService._persist_verified_candidates`, o bloco `replace_on_success` só remove marcadores `yts:presence:` antigos quando `verified_ext_ids` é **não vazio**. Se a busca ao vivo retorna `status = "ok"` com `0` torrents válidos, o marcador fantasma `yts:presence:` permanece indefinidamente no `data/sources.db`.

## 3. Decisão Arquitetural

1. **Zero Scraping HTML (`DEC-005` rejeitada):** Toda a hidratação permanece sobre a **API JSON v2** (`list_movies.json`, `movie_details.json`), que já expõe os mesmos metadados do site sem custo de parsing HTML nem bloqueios agressivos de DOM.
2. **Prioridade configurável de Mirrors (`DEC-001`):** `YIFYAdapterConfig` ganha o campo `mirror_strategy: Literal["official_first", "accel_first"]` (padrão configurável via UI de Fontes de Dados). Quando `official_first` estiver ativo, tenta `yts.mx` / `yts.lt` antes de `movies-api.accel.li` (com fallback automático caso algum domínio esteja bloqueado pelo provedor de internet/Cloudflare).
3. **Filtro na Ingestão Stage 1B (`DEC-003`):**
   - `_movies_to_presence_candidates` e `_movies_to_candidates` validam `info_hash` (mínimo 32 caracteres hexadecimais) e `seeds >= 1`.
   - Na persistência (`persist_sync_candidates`), quando `mainstream_session` estiver disponível, `imdb_id`s pertencentes a `tvSeries` / `tvMiniSeries` são descartados para `yify`.
4. **Auto-Cura no Stage 2 JIT (`DEC-002`):**
   - Em `SourcesRegistryService.get_releases_for_imdb`, se `outcome.status == "ok"` e `not outcome.releases` para uma busca padrão (`not q_override`) onde existiam apenas marcadores `yts:presence:*` (ou `replace_on_success=True`), os marcadores `yts:presence:*` daquela obra são removidos do `sources.db` e os caches (`discovery_cache`, `catalog_cache`) são invalidados.
5. **Poda de Incompatibilidade (`DEC-004`):**
   - `prune_obsolete_releases` (quando `mainstream_session` é fornecido) remove também marcadores `yts:presence:*` cuja obra em `mainstream.db` seja `tvSeries` ou `tvMiniSeries`.

---

## 4. Alternativas Consideradas e Rejeitadas

- **Scraping HTML direto do site web do YIFY (`DEC-005`):** Rejeitada porque seria 20–50x mais lenta para ~60k títulos, quebraria a cada mudança de markup HTML e sofreria bloqueios Cloudflare, enquanto a API JSON v2 dos próprios domínios oficiais entrega os dados estruturados diretamente.

---

## 5. Consequências

- **Positivas:** Eliminação progressiva de títulos fantasmas no filtro `yify` do **Explorar**; alinhamento fiel entre o catálogo exibido e os torrents baixáveis no modal; remoção automática de séries erroneamente indexadas como filmes pelo espelho `yts.pw`.
- **Negativas / Trade-offs:** Em redes onde `yts.mx`/`yts.lt` estiverem bloqueados por DNS/Cloudflare, a estratégia `official_first` adicionará alguns segundos de fallback até cair para `movies-api.accel.li` (mitigado pelo Circuit Breaker de host já existente).
